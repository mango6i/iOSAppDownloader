# iOSAppDownloader v1.0.7

## 2026-10-13 发布（2026-10-11 修订，保持版本号）

- 每次主动登录 / 重新登录前清理旧本地凭据和 Cookie，失败则停止登录，不使用旧会话补救；验证码续接保留当前挑战。这不等于撤销 Apple 服务端设备信任，不能保证每次弹出手机验证。
- 修正构建机字体差异引发的文字高度检查误报，按实际宽度检查换行文本，并增加长状态提示滚动检查；构建日志包含组件检查结果。
- 登录成功后点击“确定”同时关闭设置 / 登录窗口并回到主界面，保留已登录状态；登录失败或等待验证码时不关闭窗口。
- 保留远端弹窗不透明背景及长文案 / 状态卡片滚动修复，清除已弃用的独立 Python 认证及打包依赖，避免两套方案混在源码中。
- 清理源码中的旧组件大文件；构建前从官方准备固定版本组件并校验双重 SHA-256，成品仍完整内置。发布自动检查成品，并同步同版本标签，确保源码归档与新版源码一致。
- 修复点击登录立即报 `name '_LOCAL_PROXY_PORTS' is not defined`：恢复正常登录依赖的本地代理端口定义，新增实际登录入口、自动代理回退和未定义名称检查，并将自动代理检测纳入成品检查。
- 将原版后端从 Kosthi/ipatool-rs 0.1.8 替换为官方 majd/ipatool 2.7.0，保留来源、MIT 许可及 SHA-256。
- 接入新版签名认证、认证重定向和瞬时错误处理，支持邮箱及手机号 Apple ID。
- 正确识别“命令正常结束但仍需要验证码”，仅在认证成功并确认账号状态后显示登录成功。
- 验证码固定使用首次挑战的网络线路，不自动换线路重复提交，也不自动重新发起无验证码登录。
- 将组件初始化、网络和认证错误如实显示，不再把所有提交失败都归为“验证码错误”或断言是大陆网络限制。
- 支持取消正在进行的登录；所有线路共用总超时，退出时停止组件进程。
- Windows HOME、账号状态目录与运行组件缓存分别隔离；每次运行使用独立账号目录及随机加密口令，正常退出删除账号凭据和 Cookie，保留非敏感组件缓存。
- 适配新版官方版本列表与历史版本下载参数，接入官方版本号 / 日期补全（最多补三条，额外查询不超过 15 秒），仍保留免登录资料和空列表回退。
- 仅对已确认免费的应用尝试一次获取许可，不自动购买付费应用。
- 增加接口回归检查和成品离线检查，修正双重认证提示区域高度；EXE 仍为 iOSAppDownloader_v1.0.7.exe。

本次不接入 MCP 服务及 macOS/tvOS/watchOS/visionOS 界面，不恢复已弃用的独立 Python 认证方案。Apple 是否要求双重认证、是否推送手机通知由其服务端决定，清理本地会话不能强制服务端每次发送通知。

用户已确认此前测试版真实账号登录成功；新增重登录清理规则已通过自动检查，尚未使用真实账号验证。当前未接入自动撤销 Apple 服务端本机信任的接口。33 项回归检查通过，成品发布前另做离线检查，但不等于真实账号全流程验证；历史版本下载未在自动检查中使用真实账号验证。

## English

This v1.0.7 revision switches the original Windows backend to the unmodified
official majd/ipatool v2.7.0. It integrates signed authentication/redirect
handling, phone-number Apple IDs, official version discovery/metadata and
historical IPA downloads. The GUI correctly handles the exit-zero 2FA prompt,
confirms authenticated account status, and never automatically replays a code
on another route or restarts password-only sign-in after verification.

Cancellable requests share one timeout budget. Each app run has an isolated
Windows home/state directory and random keychain passphrase. Normal exit
removes credentials/cookies and stops child processes; verified non-secret
runtime assets remain in a separate cache. Paid apps are never auto-purchased.
Regression and packaged smoke checks were added, including the 2FA text layout.
Confirming the successful sign-in notice now closes the settings/sign-in window
and returns to the main window without signing out. Failed or pending sign-ins
leave the settings window open.

Each explicit password sign-in now clears the previous local account and
cookies first; a cleanup failure stops sign-in. Verification-code continuation
keeps its current challenge state. This does not revoke Apple-side device trust
or guarantee a fresh verification notification.

MCP and other-platform interfaces are not exposed. The abandoned independent
Python authentication implementation is not used. Apple controls 2FA and device
notifications. The user confirmed successful real-account sign-in in the earlier
test build; the new re-login cleanup behavior passed automated checks but has
not been verified with a real account. All 33 regression checks passed; the
packaged executable is checked offline before publication. Wrapped status text
is checked at its actual width, including scroll reachability for long messages,
rather than using a font-dependent preferred-size hint.
Automatic Apple-side device-trust revocation is not integrated. Automated tests
do not validate real-account IPA downloading.
